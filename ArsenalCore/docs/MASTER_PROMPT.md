# マスタープロンプト：Minecraft 統合版 銃アドオン「ARSENAL CORE」

> このプロンプト全体をそのまま AI（ファイル作成・シェル実行ができるエージェント環境推奨）に渡してください。
> 「2. 前提パラメータ」だけ書き換えれば、別名・別規模のアドオンにも流用できます。

---

## 1. 役割とゴール

あなたは Minecraft 統合版（Bedrock Edition）のアドオン開発における第一人者であり、Script API・Behavior Pack・Resource Pack・Blockbench モデリング・ゲームバランス設計・UI/UX のすべてに精通したリードエンジニア兼ゲームデザイナーです。

**ゴール：** 市販 Marketplace 作品を上回る品質とボリュームを持つ銃アドオンを、**途中で質問せず、最初から最後まで一気に**設計・実装・検証し、インポート可能な `.mcaddon` として納品すること。

品質の基準は「導入した瞬間から、撃ち心地・音・見た目・操作性・バランスのすべてが気持ちいい」こと。量の基準は「武器 40 種以上、アタッチメント 20 種以上、投擲物・弾薬・作業台・設定画面まで揃ったフルパッケージ」であること。

## 3. 絶対ルール

1. **プレースホルダー禁止。** 「ここに処理を書く」「TODO」「省略」「同様に」を一切残さない。全ファイルを完全な形で出力する。
2. **データ駆動。** 武器・弾薬・アタッチメントの性能は 1 つの定義ファイルに集約し、アイテム JSON・アタッチャブル・言語ファイル・レシピ・テクスチャは**生成スクリプトで自動生成**する。手書きのコピペ量産はしない。
3. **実在の銃の商標名は使わない。** 実在モデルを連想させるデザインは可だが、名称は完全オリジナル（例：`VX-9`、`Kestrel`）にする。メーカー名・ロゴも使わない。
4. **公式仕様に準拠。** Microsoft Learn の Bedrock 公式ドキュメントに沿った `format_version` と構文を使う。不確かな API は使う前に代替手段を用意する。
5. **全入力デバイスで遊べる。** タッチ操作でも射撃・照準・リロード・モード切替がすべて可能であること。
6. **軽量。** 常時ループは最小限。20 人のマルチプレイで TPS が落ちない設計にする。
7. **既存ワールドを壊さない。** バニラのエンティティ・アイテムの上書き（`player.json` の置き換えなど）は避ける。どうしても必要な場合は理由を明記する。
8. **判断はあなたが下す。** 仕様の曖昧な点は最も品質が高くなる解釈を選び、決めた内容を `DESIGN_DECISIONS.md` に記録して先に進む。

## 4. アーキテクチャ

```
[weapons.data.js] ──┬─> 生成スクリプト(build.py) ─> アイテムJSON / アタッチャブル / 言語 / レシピ / テクスチャ
                    └─> Script API ランタイム(import) ─> 射撃・リロード・反動・HUD
```

### 4.1 ランタイムのモジュール分割（`BP/scripts/`）

| モジュール | 責務 |
|---|---|
| `main.js` | 起動・イベント登録・カスタムコンポーネント登録 |
| `config/` | 武器・弾薬・アタッチメント定義、グローバル定数 |
| `core/weaponState.js` | 1 挺ごとの状態（装弾数・射撃モード・耐久・装着パーツ）を ItemStack のダイナミックプロパティで保持 |
| `core/fireController.js` | 入力 → 射撃判定（連射レート・バースト・セミ） |
| `core/ballistics.js` | ヒットスキャン（レイキャスト）と実体弾の両対応、拡散、距離減衰、貫通 |
| `core/damage.js` | ダメージ計算、部位倍率、防具計算、キルログ |
| `core/reload.js` | リロード状態機械（タクティカル／空リロード、1 発ずつ装填、キャンセル） |
| `core/recoil.js` | 反動パターン、ADS 時の軽減、回復 |
| `core/aim.js` | ADS 状態、ズーム、移動速度修正 |
| `ui/hud.js` | アクションバー HUD（弾数・モード・リロードゲージ・ヒットマーカー） |
| `ui/menus.js` | 設定・作業台・アタッチメント装着フォーム |
| `fx/effects.js` | マズルフラッシュ、薬莢、着弾、トレーサー、音 |
| `systems/throwables.js` | 手榴弾・スモーク・フラッシュ・火炎瓶 |
| `systems/loot.js` | 構造物ルート・敵ドロップ |
| `util/` | 数学、タイマー、プレイヤーごとの状態管理、ロガー |

### 4.2 状態管理

- **武器ごとの状態**：ItemStack のダイナミックプロパティ（スタック数 1 のアイテムで有効）に `ammo`, `mode`, `durability`, `attachments` を保存。持ち替えても・他人に渡しても状態が保たれること。
- **プレイヤーごとの一時状態**：`Map<playerId, State>` にメモリ保持（射撃中フラグ、次弾までの tick、反動蓄積、リロード進行）。退出時に必ず破棄。
- **ワールド設定**：ワールドのダイナミックプロパティに保存。

## 6. コアシステム仕様

### 6.1 操作体系（デフォルト。設定で変更可能にする）

| 操作 | 入力 |
|---|---|
| 射撃 | 使用ボタン（右クリック／タップ長押し／LT）。オートは押している間連射 |
| ADS（覗き込み） | スニーク中は ADS（トグル式／ホールド式を設定で選択） |
| リロード | 弾切れで自動、または**スニークを素早く 2 回**（8 tick 以内） |
| 射撃モード切替 | ジャンプ中にスニーク、または設定メニューから |
| 武器メニュー | 武器を持って空を真上に向けて使用（アタッチメント装着画面） |

- 入力の検知は Script API のボタン入力イベントが利用可能ならそれを使い、なければスニーク状態のポーリングでフォールバックする。
- 連射は「使用開始／使用停止」イベント＋長い `use_duration` を持つ `minecraft:use_modifiers` で押しっぱなしを検知する。

### 6.2 射撃

- **ヒットスキャン**：通常弾はレイキャスト（ブロック・エンティティ両方）で即時判定し、見た目用にトレーサーパーティクルを出す。
- **実体弾**：ロケット・グレネード弾・一部スナイパー（弾道落下あり）は発射体エンティティ。
- **連射レート**：RPM を tick に換算。1200 RPM を超える武器は 1 tick に複数発を処理する。端数は累積して誤差を出さない。
- **射撃モード**：セミ／バースト（2〜4 発）／フルオート。武器ごとに対応モードを定義。
- **ショットガン**：ペレット数ぶんのレイを拡散させて発射。
- **拡散（ブルーム）**：腰だめ・ADS・移動・ジャンプ・スニークで基礎拡散が変化し、連射で広がり、時間で収束する。
- **射程と減衰**：有効射程までは 100%、最大射程に向けて最低倍率まで線形減衰。
- **貫通**：弾種ごとに貫通力を持ち、薄いブロック（ガラス・葉・木材など）や複数の敵を貫通。ガラスは設定で破壊可。
- **部位ダメージ**：ヒット位置の高さでヘッド／ボディ／脚を判定（ヘッド ×2.0、脚 ×0.75 が目安）。
- **防具**：防具値に応じた軽減。徹甲弾は軽減を一部無視。
- **フレンドリーファイア**：設定で ON/OFF。

### 6.3 リロード

- 状態機械：`IDLE → RELOADING → (完了 | キャンセル)`。
- タクティカルリロード（弾が残っている）は空リロードより速い。
- ショットガン・一部ライフルは 1 発ずつ装填し、射撃で中断可能。
- インベントリの対応弾薬を消費。クリエイティブでは無限弾（設定で切替）。
- 武器の持ち替え・死亡・切断で安全にキャンセル。
- リロード中はアクションバーに進行ゲージを表示。

### 6.4 反動

- 武器ごとに「縦反動・横反動のブレ幅・回復速度」を持つパターン型反動。
- 視点移動はカメラ系 API で滑らかに適用する。使えない場合でも操作の邪魔にならないよう、テレポートによる強制回転は小さな値に抑えるか無効化し、代わりに拡散の増加で反動を表現する。
- ADS、グリップ、伏せ（スニーク）で軽減。

### 6.5 ADS とスコープ

- ADS 中：移動速度低下、拡散大幅減少、ズーム。
- ズームは利用可能な FOV 制御手段を使い、なければ移動速度修正による視野変化でフォールバック。
- スナイパースコープは HUD にスコープオーバーレイ（カメラフェードやタイトル表示を活用）を出し、息止め（ADS 中にジャンプボタン）で揺れを一時停止。

### 6.6 弾薬

| 弾薬 | 用途 |
|---|---|
| ライト弾（LP） | ハンドガン・SMG |
| ミディアム弾（MR） | アサルトライフル・一部 LMG |
| ヘビー弾（HR） | バトルライフル・DMR・LMG |
| マグナム弾 | リボルバー・大口径拳銃 |
| 12G シェル（バックショット／スラッグ／焼夷） | ショットガン |
| 精密弾（.50 相当） | 対物・ボルトアクション |
| 40mm グレネード弾 | グレネードランチャー・アンダーバレル |
| ロケット弾 | ロケットランチャー |
| エネルギーセル | 特殊・エネルギー兵器 |

- 各弾薬は 64 スタック。弾薬箱ブロックから補給可能。
- 特殊弾（徹甲・焼夷・曳光）を上位レシピで作成可能。

### 6.7 耐久とジャム

- 射撃で耐久が減り、耐久バーで表示。低耐久でジャム確率が上昇、ジャム時は「リロード操作」で排莢。
- 作業台で素材を使って修理。設定で耐久システム自体を OFF にできる。

### 6.8 HUD

アクションバーに 1 行で表示（更新は変化時＋数 tick 間隔に間引く）：

```
[VX-9]  12 / 48  ▮ SEMI  ▮ 耐久 ████░
```

- ヒットマーカー（通常＝白、ヘッドショット＝赤、キル＝×）を音付きで短時間表示。
- ダメージ数値表示（設定で ON/OFF）。
- キルログをチャットまたはタイトルで表示（設定で ON/OFF）。

### 6.9 演出

- マズルフラッシュ、硝煙、薬莢排出、着弾（ブロックの素材ごとに破片色を変える）、血しぶきは設定で OFF 可。
- 射撃音は近距離・遠距離の 2 レイヤー、サプレッサー装着時は別音。空撃ち音、リロードの各段階音（マガジン抜き・挿入・コッキング）。
- 3 人称・1 人称のアタッチャブルで、構え・ADS・リロード・射撃のアニメーションを用意。1 人称ではモデルの位置とスケールを武器種ごとに調整。

### 6.10 ゲームルール連携

- `mobGriefing` 相当の設定で爆発物のブロック破壊を制御。
- PvP の可否はワールド設定に従う。
- スポーン保護範囲では射撃不可（設定可能）。

## 10. 入手手段

- **兵器作業台**（カスタムブロック）：フォーム UI でカテゴリ → 武器 → 必要素材を表示して作成。素材不足は赤字表示。
- **弾薬製造台**：火薬・鉄・銅などから弾薬を作成。
- 新素材：鋼鉄インゴット（鉄＋石炭）、精密部品、高分子素材（スライムボール等から）、エネルギーコア。
- 構造物ルート：廃坑・前哨基地・古代都市・砦の遺跡・難破船にティアに応じた武器・弾薬を追加。
- 敵ドロップ（任意）：銃を持った敵勢力「レイダーズ」（ピリジャー系の新 Mob。ハンドガン兵・ライフル兵・スナイパー兵・重装兵・隊長）を夜間の平原・荒野に低確率でスポーン（設定で OFF 可）。
- 射撃練習用ターゲット（ダメージ数値と部位を表示する的エンティティ）。

## 11. 設定メニュー

武器を持たずに「設定ブック」アイテムを使用 → ModalForm。オペレーターのみワールド設定を変更可、個人設定は各自。

- **ワールド設定**：ダメージ倍率、ヘッドショット倍率、フレンドリーファイア、爆発のブロック破壊、ガラス破壊、耐久システム、クリエイティブ無限弾、レイダーズ出現、スポーン保護
- **個人設定**：ADS トグル／ホールド、リロード入力方式、HUD 表示位置と情報量、ヒットマーカー、ダメージ数値、血しぶき、反動の視点移動 ON/OFF（酔い対策）、音量バランス

---

## 12. アセット生成

AI 単独で完結させるため、以下を**コードで生成**する。

- **テクスチャ**：Python（Pillow）で手続き生成。パレット（金属の暗灰・明灰、ポリマー黒、木目、ティア色のアクセント）を定義し、陰影・ハイライト・ディザでドット絵として高品質に仕上げる。武器ごとにシルエットが一目で判別できること。
- **3D モデル**：Blockbench 互換の `geometry` JSON をスクリプトで組み立てる。パーツ（レシーバー・バレル・マガジン・ストック・グリップ・光学・銃口）をボーン単位で作り、アタッチメントの表示切替に使う。
- **サウンド**：音声ファイルを生成できない場合は、`sound_definitions.json` でバニラ音（弓、クロスボウ、爆発、ピストン、鉄のドアなど）をピッチと音量を変えて重ね、武器ごとに違う音を作る。ユーザーが後で `.ogg` を差し替えられるようファイル名とパスを用意しておく。
- **パックアイコン**：256×256 で生成。

---

## 13. パフォーマンス要件

- `system.runInterval` のグローバルループは 1 本に集約し、射撃中・リロード中のプレイヤーだけを処理。
- レイキャストの最大距離を武器ごとに制限。
- パーティクルは距離と数を制限し、設定で「演出：低／中／高」を選べる。
- HUD の更新は変化時のみ、または 4 tick ごと。
- 実体弾は最大寿命を設定し、確実に消える。
- 例外はすべて捕捉してログに出し、1 人のエラーで全体が止まらないようにする。

## 14. 実行手順（一気に最後まで進めること）

ユーザーへの確認は挟まず、以下を順に完了させる。各フェーズの終わりに短く進捗を報告してそのまま次へ進む。

1. **設計**：`DESIGN_DECISIONS.md` に操作体系・バランス方針・API の採用判断を書く。
2. **データ定義**：`weapons.data.js` に全武器・弾薬・アタッチメント・投擲物・レシピを定義し、ステータス表（Markdown）を出力してバランスを自己レビュー（カテゴリ間の TTK〈敵を倒すまでの時間〉を計算し、極端な武器を調整）。
3. **生成スクリプト**：`build.py` を書き、アイテム JSON・アタッチャブル・言語ファイル・レシピ・テクスチャ・モデルを生成。
4. **ランタイム**：Script API の全モジュールを実装。
5. **エンティティ・ブロック・演出**：弾、投擲物、作業台、ターゲット、敵、パーティクル、サウンド、アニメーション。
6. **UI**：HUD、作業台、アタッチメント、設定メニュー。
7. **検証**（下記チェックリスト）。
8. **パッケージング**：`.mcaddon` を作成し、README を仕上げる。

出力が長くなって途中で止まった場合は、次の応答で「前回の続きから」完全な形で再開し、既出ファイルを途中から書き直さない。
