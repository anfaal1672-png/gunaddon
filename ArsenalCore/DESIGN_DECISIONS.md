# ARSENAL CORE — 設計判断の記録

マスタープロンプトの「判断はあなたが下す」に従い、仕様があいまいな点・技術的な制約に当たった点で採用した判断とその理由をまとめます。

## 1. 対象バージョンと API

| 項目 | 採用 | 理由 |
|---|---|---|
| ゲーム | 統合版 1.26.50 以降（`min_engine_version` 1.26.50） | ビルド時点（2026-09）の最新安定版。Mojang 公式サンプル `bedrock-samples` 1.26.50.4 で確認 |
| `@minecraft/server` | 2.10.0 | npm の `latest` タグ（安定版）。ベータ API は一切不使用 |
| `@minecraft/server-ui` | 2.2.0 | 同上 |
| 実験的機能 | 不要 | 安定版の API・コンポーネントのみで構成 |
| バージョン定数 | `tools/weapons.data.js` の `MIN_ENGINE` / `SCRIPT_MODULES` の 1 か所 | manifest は生成時にここから作られる |

スクリプトは公式の型定義（`@minecraft/server` 2.10.0 の `index.d.ts`）に対して `tsc --checkJs` で全ファイルを型チェックしており、存在しないメソッドや引数の誤りはビルドで検出されます。

## 2. データ駆動の構成

`tools/weapons.data.js` を唯一の定義ファイルにしています。

- **ランタイム**：そのまま `BP/scripts/config/weapons.data.js` にコピーされ、スクリプトが import します。
- **生成スクリプト**：`node` 経由で JSON 化し、アイテム・アタッチャブル・3D モデル・テクスチャ・アイコン・アニメーション・言語・レシピ・ルートテーブルを生成します。

武器を 1 行足せば、モデル・アイコン・アニメ・言語キー・作業台レシピまで自動で揃います。

## 3. 射撃・ダメージ

### 3.1 無敵時間（i-frame）対策
Bedrock はダメージ後に約 10 tick の無敵時間があるため、`applyDamage` だけを使うと 600 RPM 以上の連射がほぼ吸われます。そこで次の方式にしました。

- 被弾演出・ヘイト・キル帰属のための「エンジン経由のダメージ」は、対象ごとに 10 tick に 1 回、0.5 だけ与える
- 実ダメージは体力コンポーネントを直接減算する
- **致死ダメージだけは必ずエンジン経由**（大きな値で `applyDamage`）。不死のトーテム、死亡メッセージ、ドロップ、キル帰属が正しく動きます

### 3.2 防具
モブの防具値はスクリプトから読めないため、防具軽減は `minecraft:equippable` の `totalArmor` / `totalToughness` を持つ対象（プレイヤー）に、バニラと同じ式で適用します。徹甲弾・一部武器は `ap`（防具無視率）で防具値を割り引きます。耐性エフェクトも反映します。

### 3.3 弾道
- 通常弾：ヒットスキャン（ブロックとエンティティのレイキャスト）。見た目は速度付きの曳光パーティクルで表現
- 狙撃銃：**スクリプトで毎 tick 進める実体弾**（弾道落下あり）。エンジンの投射物より正確で、貫通も同じ処理で扱えます
- 40mm・ロケット・投擲物：スクリプトの物理シミュレーション＋見た目だけのエンティティ（`arsenal:projectile`）。跳ね返り・貼り付き・信管・誘導を完全に制御できます
- 貫通：ブロックの種類ごとの貫通コスト（ガラス 0、葉 0.5、木 1、土 1.5、石 2.5、黒曜石・岩盤は不可）と武器の貫通力で判定。貫通のたびに威力が減衰

### 3.4 連射レート
1 tick = 1/20 秒なので、RPM を「1 発あたりの tick（小数）」に換算し、端数をタイマーに積み残して誤差を出しません。1 tick に複数発が必要な場合もループで処理します（最大 1200 RPM までは 1 tick 1 発）。

## 4. 入力

| 操作 | 実装 |
|---|---|
| 射撃 | `itemStartUse` / `itemStopUse`（長い `use_duration` を持つ `minecraft:use_modifiers`）。`itemStartUse` が来ない環境向けに `itemUse` のフォールバックも用意 |
| ADS | スニーク（`player.isSneaking`）。トグル式は `playerButtonInput` で切り替え |
| リロード | 弾切れで自動、またはスニークを 8 tick 以内に 2 回（`playerButtonInput`）。ジャムの解消も同じ操作 |
| 射撃モード | ジャンプボタンを押したまま空中でスニーク。武器メニューからも変更可能（タッチ操作で両指が使えない場合の代替） |
| 武器メニュー | 真上（ピッチ -80° 未満）を向いて使用 |
| 息止め | スコープで ADS 中にジャンプ |

すべてタッチ・コントローラー・キーボードの標準ボタン（使用・スニーク・ジャンプ）だけで操作でき、PC 専用キーは使っていません。

## 5. 見た目（3D モデル・アニメーション）

### 5.1 3D モデルは手続き生成
45 種すべての銃を、パーツ（レシーバー・銃身・ハンドガード・マガジン・ストック・グリップ・光学・銃口）を組み合わせるビルダーで生成しています。形式は Blockbench 互換の `format_version 1.16.0` ジオメトリで、Blockbench で開いて手直しすることもできます。テクスチャは 1 丁ごとに 64×64 の素材アトラス（16 素材タイル）を生成し、仕上げ（ブラック・タン・OD・アークティック・スチール・ウッド等）とティア色のアクセントを反映しています。

### 5.2 一人称の位置合わせは計算で求めた
Blockbench と同じボーン変換を Python で再実装し（`tools/riggen.py`）、Bedrock Wiki の Attachable ガイドにある一人称の腕ポーズ（rightArm 回転 [95,-45,115]、位置 [13.5,-10,12]）を使って、**銃口が視線方向を向く銃ボーンの回転・位置を逆算**しています。三人称では、スクリプトから再生する構えポーズ（腕を視線方向に上げる）に合わせて同様に計算しています。

> ⚠ この環境ではゲーム本体を起動できないため、画面上の最終的な見え方は実機で確認していません。ずれていた場合は `tools/riggen.py` の `CAM`（一人称カメラ位置）と `HIP_NUDGE`（カテゴリ別の腰だめ補正）を調整して再ビルドしてください。

### 5.3 `player.json` を上書きしない
構え・反動・リロード・ADS の腕の動きは、プレイヤーの定義を置き換えずに `Entity.playAnimation` で再生しています。停止条件は Molang の `q.equipped_item_any_tag`（武器ごとのアイテムタグ）で、持ち替えるとクライアント側で即座に止まります。ほかのアドオンとの競合を避けるための判断です。

### 5.4 アタッチメントは 3D モデルに表示しない（制約）
アタッチャブルは「持っている ItemStack ごとの状態」を Molang から参照できません。スタックごとに見た目を変えるには `player.json` を上書きしてエンティティプロパティを追加する必要があり、上の方針と衝突します。そのため、アタッチメントは **説明文（Lore）・HUD・武器メニュー**で表示し、性能には完全に反映しています。3D モデルには各武器の標準装備（DMR・狙撃銃のスコープ、ラヴェジャーのドラムなど）を表示しています。

### 5.5 ADS の構えはスクリプトの ADS 状態で切り替える（1.0.2 で変更）
1.0.1 まではクライアント側 Molang（`q.is_sneaking`）で腕を動かしていましたが、「切り替え」式の ADS では見た目が腰だめのままになり、スコープのない銃で「覗いてもアイアンサイトにならない」ことがありました。1.0.2 からは、スクリプトが ADS に入った時点で武器ごとの ADS アニメーション（`animation.arsenal.ads.<id>`、照準線を画面中央に合わせる位置。`tools/riggen.py` の `ads_arm_offset`）を `playAnimation`（コントローラー `arsenal_ads`）で再生し、抜けるときに止めます。倍率スコープ（2 倍・4 倍・8 倍・サーマル。アタッチメントで付けたものを含む）は銃を画面の下へ下ろす `animation.arsenal.ads_scope` を再生します。

### 5.6 スコープ
- FOV はゲームの制約で 30〜110 の範囲です。8 倍スコープは FOV 30 に加え、鈍足エフェクトによる視野変化でさらに拡大します（プレイヤーの「FOV 効果」設定に依存）
- **揺れの演出は廃止**（1.0.2）：以前は `camera.addShake`（回転）を 1 秒ごとにかけていましたが、FOV 30 前後まで拡大していると揺れも拡大され、視点が激しく震えて狙えませんでした（とくにスマホ）。息止め（ADS 中にジャンプ）は「3 秒間拡散を 35% にする」効果として残しています。倍率スコープ中の反動の画面揺れも位置シェイクに変えて弱くしています
- **全画面のスコープ表示**（1.0.2 で追加）：当初は HUD が壊れる危険を避けて採用していませんでしたが、要望を受けて **最小限の追加だけ** で実装しました。`ui/hud_screen.json` で `root_panel` の先頭に 1 つパネルを足し（既存要素の置き換えなし）、タイトルの文字列に画面に出ない書式コードの目印（`§a§r§s§n` ＋種類の数字）が含まれているときだけスコープ（黒い枠＋レティクル）やドット／ホロのレティクルを表示します。目印だけのタイトルは枠ごと隠します（`hud_title_text` の `title_frame` に表示条件を付けたもの。中身はバニラと同じ）。アクションバーは現行の HUD では文字列を参照できるグローバルバインディングがないため、タイトルを使っています

## 6. HUD
アクションバー（または個人設定でサブタイトル）に 1 行で表示し、弾数・射撃モード・耐久・リロード進行・過熱・充電・ロックオン・ヒットマーカー・ダメージ数値を出します。アイコンはカスタムグリフ（`font/glyph_E1.png`、U+E100〜）で描いています。HUD の文字表示は JSON UI を使わず、スコープ表示（5.6）だけが JSON UI です。更新は変化時と 4〜10 tick 間隔に間引いています。

## 6.5 射撃の入力（1.0.2）
- 押下の記録は 1 回分まで。フルオートは撃った時点で使い切り、指を離した後に余分な弾が出ません
- バーストは押下 1 回につき 1 バースト。1.0.1 まではバースト開始時に押下の記録を消費しておらず、**1 回のタップで弾切れまでバーストが続く**不具合がありました
- 個人設定「フルオートの撃ち方」：「タップで撃ち始め・もう一度タップで止める」を選ぶと、スマホで押しっぱなしにしなくても連射でき、止めるのも 1 タップです。弾切れ・リロード・持ち替え・射撃モード変更でも止まります

## 6.6 爆発と実体弾の衝突（1.0.2）
- **発射位置**：銃口が壁や地面にめり込む姿勢（真下に向ける・壁に密着）では、目から銃口までのレイで先に当たった面の手前から発射します
- **衝突判定**：毎 tick のブロックのレイ判定に加え、終点（または始点）がブロックの中なら進入点を探し直します（面の上から始まるレイの取りこぼし対策）。草花・たいまつ・光源ブロックなど水で壊れるブロックはすり抜けます
- **爆風ダメージ**：エンジンの爆発（ブロック破壊・ノックバック・ダメージ）を起こしたうえで、次の tick に「エンジンの爆発ダメージを受けていない対象」へ、バニラと同じ式（距離と遮蔽率）で爆風ダメージを与えます。二重には当たりません。射撃練習ターゲットにも表示され、撃った本人にはヒットマーカーが出ます
- 40mm の安全距離は 3 → 0.5 ブロック（至近距離で地面に撃ち込んで不発になり「すり抜けた」ように見えるのを避ける）
- **照明弾**：飛んでいる間は 1 ブロックごとに光源ブロック（明るさ 14）を付け替え、着弾後は明るさ 15 で最大 20 秒燃えます。光源はワールド設定「光源ブロック（フラッシュライト・照明弾）」に従い、弾が消えるときと 20 秒の期限で必ず片付けます

## 6.7 読み込まれていないチャンク（1.0.2）
遠くへ撃つと弾道が読み込み範囲の外（スマホの描画距離は短い）に出て、`LocationInUnloadedChunkError` の警告が定期的に出ていました。弾道・実体弾・爆発は `Dimension.isChunkLoaded` とワールドの高さで先に確認し、読み込まれていない手前で止めます（チャンク単位で 1 tick だけキャッシュ）。境界で起きた同種の例外はログに出しません。

## 7. 反動
- 画面揺れ（`camera.addShake`）＋ブルーム（拡散の増加）＋反動アニメーション
- 視点の跳ね上がり（`setRotation`）は個人設定で「オフ／弱（既定）／強」。**縦反動の 75% は撃ち止めると自動で戻ります**（ランタイムテストで、回復が無いと長い連射で真上を向いてしまう問題を見つけて追加）
- 反動の跳ね上がりは最大 -78° で止め、真上（-80° 未満）の武器メニュー操作と衝突しないようにしています

## 8. 耐久とジャム
- 射撃のたびにアイテムを書き換えると、一人称の持ち替えアニメーションが走ったり、端末によっては「使用」が途切れて押しっぱなし扱いが残る（＝指を離しても射撃が止まらない）ため、**残弾と損耗は指を離した時点・撃ち止めて 0.6 秒後・持ち替え時にまとめて 1 回で書き込みます**（1.0.2 で残弾も同じ扱いに変更）。押している間の書き換えが 0 回であることはランタイムテストで確認しています
- 耐久が 25% を切るとジャム率が上昇（最大約 3%）。ワールド設定で耐久システムごと無効化できます

## 9. 効果音
外部素材を使わず、**全 144 ファイルを numpy/scipy で合成**しています（`tools/audiogen.py`）。銃声は「超音速クラック＋破裂音＋低音の衝撃＋残響」の 4 層、13 種の銃声プロファイル × 3 バリエーション＋遠距離層。機構音（マガジン・ボルト・ポンプ・中折れ・ベルト等）、爆発、UI 音も合成です。`ArsenalCore_RP/sounds/arsenal/` 以下の同名 `.ogg` を差し替えれば好きな音に変えられます。

射撃音は近距離層と遠距離層を分け、聞き手の距離に応じて鳴らし分けています（24 ブロック以遠で遠距離層、最大 220 ブロック）。音量はプレイヤーごとの設定を反映するため、受け手ごとに個別に再生しています。

## 10. 入手

- 素材（鋼鉄・精密部品・高分子・エネルギーコア）と設備（兵器作業台・弾薬製造機・弾薬箱）は通常の作業台レシピ
- 武器・アタッチメント・投擲物は兵器作業台（フォーム UI）、弾薬は弾薬製造機
- **レジェンダリー 4 種は作成不可**（古代都市・砦の遺跡・レイダー隊長のドロップ）
- 構造物ルートは、バニラのルートテーブル 9 種（1.26.50 の内容）をコピーして ARSENAL のプールを追加する方式です。同じテーブルを上書きする別アドオンとは、後から読み込まれた方が優先されます
- ルートやレイダーのドロップで見つけた銃は、見つけた瞬間にランダムな残弾と、ティアに応じたアタッチメントが付きます

## 11. レイダーズ
射撃 AI はエンティティ定義（`minecraft:behavior.ranged_attack` ＋専用の弾エンティティ）で実装し、スクリプトは銃声・マズルフラッシュ・曳光の演出だけを担当します。スクリプトに AI を持たせるより挙動が安定し、負荷も小さいためです。見た目はプレイヤーと同じ骨格の独自モデル（64×64 スキン、装備はオーバーレイ層）で、手に持つ銃はプレイヤーと同じアタッチャブルで描画されます。ワールド設定で無効にすると、自然発生した個体は出現時に取り除かれます（スポーンエッグは有効）。

## 12. パフォーマンス
- `system.runInterval` は 1 本だけ。武器を持っていないプレイヤーは手持ち確認のみ
- レイキャストは武器の最大射程まで。貫通の区間は最大 10
- パーティクルは受け手ごとに送信し、演出品質（低／中／高）と距離で間引き
- 実体弾は最大寿命つき。同時 400 発を超えると古いものから消去
- 読み込み直後と 60 秒ごとに、追跡していない見た目エンティティを掃除
- すべての処理を `safe()` で囲み、例外は同じ内容の連続出力を間引いてログに出します。1 人のエラーで全体のループは止まりません

## 13. 品質保証
`python3 tools/build.py` が生成のたびに次の 17 項目を検証し、1 つでも失敗するとパッケージを作りません。

1. JSON 構文（全ファイル）
2. manifest（UUID の一意性、BP/RP の相互依存、Script API のバージョン一致）
3. 言語キー（全アイテム・スクリプト参照キーが英日両方にあるか）
4. テクスチャ・モデル・アニメーション・レンダーコントローラーの参照整合性
5. 武器ごとの完全性（アイテム・アイコン・テクスチャ・モデル・アタッチャブル・3 種のアニメ・リロードアニメ）
6. スクリプトが参照するサウンド・パーティクル・アニメーションの実在
7. スクリプト構文（`node --check`）
8. 公式型定義による型チェック（`tsc --checkJs`）
9. 規模（武器 40 種・アタッチメント 20 種以上）
10. 商標チェック（実在の銃名・メーカー名 49 語）
11. 射撃モード定義
12. **ランタイムテスト**：Script API のモックでゲームループを実際に回し、射撃・連射・命中・リロード・弾薬消費・耐久・アタッチメント・ADS ズーム・モード切替・全 45 武器の発射・投擲物 5 種・起爆装置・地雷・設定フォーム・作業台での作成・設定の反映・持ち替え時のリロードキャンセル・反動回復・例外ゼロ、さらに 1.0.2 で「押している間に手持ちを書き換えない」「離すとすぐ止まる」「バーストは 1 タップで 3 発」「タップ切替」「爆風ダメージ」「真下・壁際に撃っても貫通しない」「照明弾の光源の片付け」「スコープ表示の印と構え」「未ロードのチャンクに触れない」を確認（54 項目。モックは読み込み範囲外に触ると実機と同じ例外を投げ、エンジンの爆発はダメージを与えない）
13. **公式 JSON スキーマ**：Mojang の bedrock-samples 1.26.50 に含まれるスキーマ（`tools/schemas/`）でエンティティ・アイテム・ブロックを検証。スキーマは未知のキーを素通しするため、エンティティのコンポーネント名はスキーマの一覧と突き合わせる（例：廃止された `minecraft:pushable` を検出）
14. **Molang**：`??` の左辺が直接の変数（`v.size`）であること。`v.color.r ?? 1` のような構造体のメンバーや式は不可
15. **アニメーション**：`bones` が空のアニメーションがないこと
16. **パーティクル**：公式スキーマ（client/particles）で検証し、未知のコンポーネント名とバニラに無いマテリアルを検出
17. **HUD（スコープ表示）**：`ui/hud_screen.json` のテクスチャの実在、スクリプト（`ui/hud.js` の `SCOPE_MARK`）と目印が一致すること、`modifications` の操作名

公式スキーマの `oneOf` には正しい JSON が複数の分岐に当てはまってしまう箇所があるため、`anyOf` として扱っています（バニラのエンティティ 128 件で誤検出がないことを確認済み。検出されるのはバニラ専用のコンポーネントと `minecraft:pushable` のみ）。

## 2.1. 見た目違い ID（光学と迷彩を 3D で見せる）

Bedrock のアタッチャブルは、アイテムのダイナミックプロパティを見て描き分けることができません。そこで **光学の見た目グループ（0 アイアン／1 ドット系／2 倍率スコープ）と迷彩（8 種）ごとに、隠しアイテムを別 ID で用意** しました（`arsenal:<武器>__o<グループ>`、`arsenal:<武器>__c<番号>`、計 806 個）。

- 隠しアイテムはクリエイティブのインベントリとコマンド補完に出さず（`menu_category: none`）、タグ（`arsenal:w_<武器>`・`arsenal:variant`）は元の武器と同じ
- スクリプトは `weaponIdOf()` で見た目違いを元の武器として扱う。持ち替えの判定キーは「元の武器 ID ＋スロット＋1 挺ごとの識別子（`a:id`）」なので、見た目の差し替えで装備し直しにはならない
- 差し替え（`retype`）はダイナミックプロパティ・耐久・名前・説明文（`getRawLore`）・`keepOnDeath`・`lockMode` をすべて引き継ぐ
- **撃っている最中は差し替えない**（1.0.2 の規則「使用中に手持ちを書き換えない」）。使用ボタンを離していて最後の射撃から 12 tick 以上たったときだけ、10 tick ごとに確かめる
- 迷彩と光学が両方あるときは迷彩の見た目を優先（組み合わせ全部を ID にすると 3 × 8 倍になり、アイテム数の予算を超えるため）
- アドオンを外す前に `/scriptevent arsenal:normalize` で元の ID に戻せる

## 2.2. HUD 2.0 の符号化

JSON UI にスクリプトから値を渡す手段は、1.0.2 と同じくタイトルの文字列だけにしました（ベータ API を使わないため）。

- タイトル = `"AC2"` ＋ 1 文字ごとの札（`SEP + キー + 桁 + 文字`、例：弾数 ` 27` → `.a0_.a12.a27`）の並び ＋ `"."` ＋ 目印 `§a§r§s§n` ＋ `§` ＋ スコープ表示の番号。フィールドとキーは `tools/data/hud.js` の `HUD2`（弾数・予備弾・モード・状態・熱・プレート・体力・方位・制圧・暗視・ゲームモードの得点と時間・連続キル・クレジット・ストリーク・測距・風の向きと強さ・大きさ・配置）
- JSON UI は「札 `.a12.` を含むか」（`(not ((#arsenal_t - '.a12.') = #arsenal_t))`）だけで判定する。スコープ表示（1.0.2、実機で動作）と同じ演算だけを使う。数字は桁ごとに 0〜9 の 1 文字ラベルを並べ、値の文字のものだけを見せる（既定フォントの数字は幅 6 px なので 6 px × 倍率の格子に置く）
- **2.0.1 までは** `(('%.Ns' * #t) - ('%.Ms' * #t))`（先頭 N 文字 − 先頭 M 文字）でフィールドを切り出していたが、実機ではスコープ表示が出るのに HUD 2.0 は何も出なかった。文字列の `*` 演算は版によって挙動が変わっており（Bedrock Wiki の型変換の項にも `#str * 1` が働かなくなったとの記載がある）、使わないことにした。ビルド時の検証で `*` を含む式を失敗にする
- 目印を含むタイトルはバニラのタイトル枠ごと隠れる（1.0.2 と同じ置き換え）
- 数字のラベルは、それぞれが「欄の条件 and 札」を持つ（欄のパネルには条件を付けない）。表示条件付きのパネルの子は、パネルが現れた直後にタイトルが変わらないと古い表示のまま残ることがあった（実機で測距の数字が出ず "m" だけ出た）。あわせて送るたびに `seq`（0〜9）を変え、同じ内容の再送でも JSON UI に評価し直させる（2.1.0）
- 方位は 2° ごとの 180 枚。上 2 桁のパネル 18 個で絞り、子は下 1 桁の札だけを見る。方位と照準の広がりは毎 tick 見て、変わったら次の tick に送る（2.1.0）
- HUD 2.0 のパネルは親パネルで「`AC2.` を含むか」、配置・大きさ・試合中・数字の欄ごとのパネルでその条件を 1 回だけ評価し、子は自分の条件（札 1 つ）だけを持つ（スマホでの毎フレームの式を減らす）
- 送るのは **ARSENAL の品を持っているとき・試合中・乗車中・ダウン中・ドローンやガンシップの操作中だけ**。それ以外はタイトルを使わず、地図やほかのアドオンの `/title` を邪魔しない
- HUD 2.0 ではアクションバーが空くので、大きな知らせ（ボスの予兆・ダウン・ウェーブ）は `announce()` がアクションバーへ出す。従来型ではサブタイトル
- ビルド時に、スクリプトの符号化で作った 64 通りの値を Python の JSON UI 式評価器で評価し、札の判定・表示条件・表示される文字の一致を確かめる（検証 24）
- 1.0.2 で HUD を消していた人・タイトル表示にしていた人は、更新後も従来型のまま（個人設定で切り替え可能）

## 2.3. 構造物の生成方式

| 段階 | 方式 | 理由 |
|---|---|---|
| 1 | 地物ルール → `structure_template_feature` が **1 ブロックの目印の構造物**（`arsenal:site_<id>`）を地表に置く | 大きな構造物を地形生成で直接置くと、ワールド設定で密度を変えられず、OFF にしても消せない |
| 2 | 目印のブロック（`arsenal:site_marker`、状態 `arsenal:kind`）の tick（40〜60 tick ごと）とランダム tick で、48 ブロック以内にプレイヤーがいれば密度の設定で抽選 | 地形生成で置かれたブロックに定期 tick が付かない場合の保険としてランダム tick も使う |
| 3 | 当たり：`structureManager.place` で本体（`.mcstructure`）を置き、宝箱に中身を詰め、守備隊を出す。外れ・OFF・ほかの構造物から 40 ブロック以内・ワールドの高さの外：目印を消すだけ | 地形を変えずに消せる |

- `.mcstructure` は `tools/gen/structures.py` が NBT（リトルエンディアン）で直接書く。ブロックの並びは x → y → z（z が最も速い）、第 2 層は -1、パレットの `version` は 1.26.50.0。状態は公式の状態一覧（`tools/vanilla/blocks.json`）で検証
- 宝箱と守備隊の出現位置はビルド時に `config/structures.gen.js` へ書き出すので、置いたあとにブロックを走査しない
- 守備隊には `arsenal_site:<番号>` のタグ。全滅で「制圧」（クレジット・経験値・チャレンジ）。記録はワールドのダイナミックプロパティ `a:sites`（最大 64 件）
- 密度：なし 0／少なめ 0.3／標準 0.6／多め 1.0（地物ルールの出現率は「多め」の値）

## 2.4. 敵 AI と予算

エンジンの行動とスクリプトの頭脳を組み合わせました。

- **エンジン**：移動・索敵・射撃のタイミング。行動グループは engage（近づいて撃つ）／hold（その場で撃つ）／move（道しるべ `arsenal:waypoint` へ向かう）の 3 つで、スクリプトがイベントで切り替える
- **射撃**：エンジンには合図（`arsenal:ai_shot`）だけを撃たせ、出現した瞬間に消して、スクリプトの弾道（難易度ごとの拡散・距離減衰・部位・防具・プレート・盾）で撃ち直す。1.0 系の弾（`raider_*_bullet`）も同じく横取り
- **頭脳**（`systems/ai/brain.js`）：役割ごとの行動（遮蔽への後退・側面への回り込み・狙撃兵の後退・衛生兵の回復・爆破兵の投擲・ドローンの発見共有・自爆・迫撃砲の間接射撃）、分隊での位置共有、デコイへの誘導、EMP・スタン
- **予算**：1 tick に考える AI は最大 8 体、各 AI は 5〜10 tick ごと（難易度で変化）、1 次元あたり 60 体を超えた分は考えない（エンジンの行動だけで動く）。遮蔽探しは 1 回 10 本のレイまで、同じ AI は 60 tick に 1 回まで
- **難易度**（ワールド設定）：やさしい／ふつう／むずかしい／ベテランで、拡散（×1.8〜×0.45）・ダメージ（×0.7〜×1.4）・思考間隔・投擲・回り込みの頻度が変わる
- 敵同士は撃ち合わない。1.0 系のワールドから来たレイダーには、読み込み時に 1 回だけ `arsenal:init` を送って新しい行動グループを付ける
- ボスは同じ頭脳に「思考のフック」で割り込む。大技は必ず予兆（音・地面の印・文字）を出し、予約した行動を tick で実行。段階と部位の体力はボスのダイナミックプロパティに保存

## 2.6. 進行

- 武器レベル 1〜30（経験値：キル 50・頭 +25・遠距離 +20・命中 1（200 tick に 10 回まで）・アシスト 15・ボス 400）。迷彩はレベル 4〜30 で解放
- アタッチメントの作成制限（ワールド設定「アタッチメント作成に武器レベルが必要」）は、**持っている武器の最高レベル** で判定（アンコモン Lv4・レア Lv10。レジェンダリーはもともとルート限定）。作業台は武器ごとの画面ではないため
- 階級 1〜50、称号 15 段階、名前の横のグリフ 10 段階（個人設定で消せる）
- チャレンジ：デイリー 3・ウィークリー 3。**実時間**（UTC）の日・週の番号とプレイヤー ID から選ぶ（ゲーム内の日は寝ると進むため）
- 保存：プレイヤーのダイナミックプロパティに JSON を分割（1 つ 30000 文字まで、`a:prog.0`…、`a:prog.n`、`a:prog.v`）。書き込みは 5 秒ごと・変化時のみ。退出の before イベントでは書けないため、最大 5 秒分の経験値は失われうる（許容）

## 2.7. ゲームモード

- アリーナは OP がアリーナツールで登録（2 つの隅・スポーン地点・丘）。ワールドのダイナミックプロパティ `a:arenas`
- 1 ワールドで同時に 1 試合。ロビー（15〜20 秒）→ 開始 → 終了（5 秒後に復元）
- **持ち物の保存**：アリーナの中心に見えない保管庫（`arsenal:storage`、54 枠。1 人 1 つ）を置き、`tickingarea` で読み込んだままにする。プレイヤーには `a:msave`（保管庫の ID・元の位置・ゲームモード・体力・チームタグ）。退出・再起動があっても、次に参加したときに保管庫へ連れて行って戻す（最大 30 回まで試行）
- **死亡**：参加者は死なない。致死ダメージをダメージ処理の「横取り」で止め（スクリプトの弾・エンジンのダメージの両方）、撃破を数えて観戦モードで待たせてからスポーン地点へ（2 秒の保護）
- 再起動したときの試合は中止（途中の状態を正しく再現するより、確実に持ち物を戻すことを優先）
- ガンゲームではキルストリーク不可、試合中はダウン制を使わない

## 2.8. 防具・装備

- プレートはボディアーマーのダイナミックプロパティ（`a:pl` 枚数・`a:pd` 損傷）。胸の防具スロットは手持ちではないので射撃中でも書き換えてよい
- 近接武器の素のダメージはエンジン（アイテムの `minecraft:damage`）、背後攻撃・溜め攻撃・特殊効果の追加分だけスクリプト。PvP の背後攻撃は倍率の上限（既定 2.0）
- 出血は体力 1 で止まる（出血だけでは死なない）。除細動器は消費せず 30 秒のクールダウン
- 設置物の上限（1 人あたり）：砲台 2・シールド 3・クレイモア 6・弾薬／医療ステーション 各 2・迫撃砲陣地 1・重機関銃座 2・対空砲 1・対装甲ランチャー 1・バギー 2
- 砲台は敵性のモブ（`monster`）だけを狙う。PvP の相手を自動で撃つ砲台は強すぎるため

## 2.9. 互換性の方針

- 1.0.2 のアイテム ID・ダイナミックプロパティのキー（`a:ammo`/`a:mode`/`a:att`/`a:at`/`a:ub`/`a:init`）は変えない。2.0 で `a:v`（形式のバージョン）・`a:cm`（迷彩）・`a:id`（識別子）を足した
- アイテムの移行：`a:v` が無ければ 1.0 系。無効になったアタッチメントだけ外して `a:v = 2`
- ワールド／個人設定の移行：欠けたキーを既定値で補う（既存の値は保つ）
- 1.0 系の敵 5 種は ID と数値を変えていない。旧弾のエンティティも定義を残し、横取りして消す
- `player.json` は上書きしない。実験的機能は使わない。スポーンルールは旧形式（1.8.0）のまま（公開スキーマは新形式なので、条件名の一覧で検証）

## 2.12. 既知の制限（2.0）

- 光学と迷彩を両方付けると迷彩の見た目になる（§2.1）
- 見た目違いのアイテムは ID が違うため、ほかのアドオンのアイテム判定（ID 指定）には元の武器として扱われない
- パレットの `version`（1.26.50.0）は実機の書き出しと異なる可能性がある。ゲームは古い／新しい版の状態を変換して読み込むが、実機で構造物の見た目を確認すること（`docs/REALDEVICE_CHECKLIST.md`）
- 乗り物の運転はエンジンの操作（`input_ground_controlled`）なので、段差の越え方や速度は実機で調整が要る
- ドローン・ガンシップの視点は `camera.setCamera("minecraft:free")`。使えない環境では通常の視点のまま操作する
- モック環境の負荷試験は実機の性能を保証しない。実機ではスマホで 20 人規模の試合を確認すること

## 2.13. 早期実行（2.0.1）

- 実機ではスクリプトの読み込み中（モジュールの最上位）と `system.beforeEvents.startup` の中は「早期実行」で、`world.getDynamicProperty` などワールドの状態に触れる関数は例外になる。`attach*()` はイベントの購読だけを行い、ワールド設定やダイナミックプロパティを読む処理は `world.afterEvents.worldLoad` 以降（または tick の中）に置く
- `W()`（ワールド設定）は、読めなかったときに既定値を返すだけでキャッシュしない。キャッシュすると、保存済みの設定がそのセッションのあいだ無視されるため
- モック環境も同じ制限を持ち（`worldLoad` の発火または最初の tick で解除）、起動時の違反はランタイムテストで検出する

## 2.13. 弾が飛ぶ・ロックオン・走る構え（2.1.0）

- **弾道**：ヒットスキャンだった銃も、狙撃銃と同じ仮想の弾（エンティティを使わない）で撃つ。1 tick ごとに弾速ぶんの区間をレイで調べ（貫通・距離減衰・部位はヒットスキャンと同じ `traceHitscan`）、重力と風で曲げる。撃った tick に最初の区間を進めるので、近距離の当たり方は変わらない。弾速は実銃より遅め（カテゴリの `bullet`）にして、20〜100 ブロックでも偏差と落下が分かるようにした。弾があふれたら古い弾から消す（C4 や手榴弾を先に消さない）
- **ロックオン**：レイがぴったり敵に当たり続ける必要があった（スマホでは難しい）。照準の中心から 8° の円錐の中で、ブロックに遮られていない敵のうち中心に近いものを捕まえ、14° 以内なら捕まえ続ける。ロック完了後は 30 tick 保つ
- **走る構え**：`animation.arsenal.sprint` を別のコントローラー（`arsenal_sprint`）で保持ポーズに重ねる。0.18 秒で構え、`q.is_sprinting` が偽になるか銃を持ち替えると `blendOutTime` で戻る。三人称は腕の回転、一人称は位置だけを動かす（一人称の腕の回転は向きが分かりにくいため使わない）
- **C4 が mob を押す**：mob（`minecraft:pushable_by_entity` を持つバニラの mob）は、当たり判定が重なったエンティティに押される。押されるかは mob 側の設定で決まり、こちらの見た目のエンティティの設定（`pushable`・`push_through`・体力の有無・当たり判定の大きさ）では変えられなかった（BDS で確認）。そこで貼り付く位置を mob の当たり判定の外側にした
- **実機での確認**：BDS（Linux 版）にアドオンを入れ、試験用のコピーにだけ `@minecraft/server-gametest` への依存と試験スクリプトを足して、シミュレートプレイヤーで撃つ・投げる・ロックオンを再現した。シミュレートプレイヤーは、生成したスクリプトと同じパックからしか扱えない（ほかのパックからは undefined になる）

## 2.14. リアルさ（2.2.0）

- **薬室の 1 発**：`st.chamber`（1 か 0）。1 発ずつ装填・リボルバー・中折れ・オープンボルトの機関銃・ランチャー・エネルギー兵器は 0。満タンの判定は `mag + (残弾あり ? chamber : 0)`
- **マガジン単位**：途中のマガジンは銃のアイテムのダイナミックプロパティ `a:mg`（JSON の配列、多い順、最大 6 本）。予備弾の表示（`reserveRounds`）は途中のマガジンを含む。弾種を切り替えると途中のマガジンも予備弾に戻す。差すマガジンの選び方は「予備弾で満タンが作れる → 満タン」「作れない → 予備弾と途中のマガジンのうち多いほう」
- **構え直す時間**：`CATEGORIES.*.ready`。走る構えが解けた tick から数え、その間は引き金を引いても撃たない（押した分は残り、構え終わると撃つ）
- **部位**：`hitZone(target, point, dir)`。当たった点は当たり判定の表面にあるので、中心からの距離ではなく「弾の向きに垂直な横ずれ」で腕を判定する（中心からの距離だと、正面のど真ん中も腕になってしまう）。効き目は `limbHit`、AI へは `onLimbHit` で知らせる
- **屋内の判定**：真上 8 ブロック以内に天井、水平 4 方向のうち 2 方向以上で 6 ブロック以内に壁。撃った者ごとに 2 秒キャッシュ（毎発 5 本のレイを撃たない）

## 2.15. ボリューム（2.3.0）

- **容量の予算**：銃 1 挺につき迷彩 12 種＋光学の見た目 2 種の見た目違いが items と attachables に 1 つずつ増える（銃 114 挺で約 1,560）。2.3 で items 1857・attachables 1697 になったため、予算を items 2200・attachables 2000 に引き上げた。テクスチャは銃の見た目違いでも共有の手続き生成なので 2.5 MB、パッケージ全体で 8.5 MB（予算 40 MB）に収まっている。これ以上迷彩を増やす場合は、見た目違いをアイテムで持つ方式の見直しが要る
- **武器レベル 40**：迷彩の解放を Lv30 より上に置くため上限を 40 にした。経験値表は同じ式を延長（Lv30 までの必要量は変わらない）
- **ボスの増援は persist**：通常の敵は `minecraft:despawn`（遠ければ消える）付きで出るが、BDS ではボスの増援が戦闘中に数秒で消えた。増援は `arsenal:persist` を付けて出し、ボスが倒れたら衰弱 III（20 秒）で確実に倒す（体力 26 の兵まで倒れる）
- **ホロウ・マザーの増援にブローターを入れない**：ブローターの破裂は敵味方を区別しないため、群れの中で破裂すると増援がまとめて倒れる（BDS で確認）
- **新しい中身は既存の仕組みで動く**：新しい銃・アタッチメント・投擲物・迷彩・敵はデータの追加だけ（アタッチメントの効果は既存の倍率・加算のキー、投擲物は既存の kind、敵は既存の役割とモデル）。新しいスクリプトの分岐は、自動擲弾銃座の発射（`fire: "gl40"`）とボスの投擲物の指定（`grenade`）だけ

## 2.16. 経路探索ミサイル（2.4.0、アリアドネ）

- **「ズルをしない」の定義**：ミサイルの見た目と当たり判定は、ほかのロケットと同じ「毎 tick レイで衝突判定する点」。道はその点が実際に通れるマスだけでつなぎ、移動は道の区間ごとにレイで確かめる。ブロックの中を通らない・ワープしない・壁越しのダメージを与えない
- **マスの判定**（`systems/pathfind.js` の `cell`）：弾が止まらないブロック（`isSolidBlock` が偽。空気・草花・液体など）は通れる。扉・トラップドア・フェンスゲートは形が向きと開閉で変わるので、隣のマスの中心から中心へのレイで 1 歩ごとに確かめる。それ以外のブロック・読み込まれていないマス・高さの範囲外は通れない。ハーフブロックや柵など、ほかの形のブロックは通れないものとして扱う（実際には通れる隙間でも、ミサイルが角に当たらないことを保証できないため）
- **探索**：6 方向（斜めに進まないので、角と角が接するだけの隙間はすり抜けない）の重み付き A*（ヒューリスティック 1.4 倍）。展開数の上限 12,000・始点から 110 ブロック・道の長さ 180。1 tick あたり 600 マス（全員の合計）の予算で少しずつ進める。マスの判定は 40 tick 覚え、ブロックの設置・破壊・爆発・扉の操作で忘れる。それでも古い判定で区間を進んでブロックに当たったら、当たる手前で止まり、そのマスを調べ直して探し直す（4 回まで。超えたら起爆）
- **直線化**：マスの中心をつないだ道を、両脇に 0.1 ブロックの余裕がある直線でつなげる限り先へ伸ばす。扉のマスを通る直線は作らない（扉のマスは中心を通る 1 歩だけ）
- **ロック**：照準の中心から 10°（保つのは 18°）の敵を、見えていなくても候補にする。道が見つかるまでロックは進まない。道が見つからなかった敵は 30 tick 候補から外す。撃ち手や目標が 1 ブロック以上動くか、道の途中がふさがれたら 10 tick ごとに探し直す（結果が出るまで前の道を使う）
- **飛行**：撃つときは銃口から道の 2 点目へ（行けなければ目の位置を経由して）。目標が動いたら道の終点を合わせ、合わせられなければ今いる場所から探し直す。探している間はその場で待つ（新しい道は今いる場所から始まるので、道とミサイルの位置がずれない）。待ちが合わせて 60 tick を超えたら起爆。速さは 0.7 から 1 tick ごとに 0.08 ずつ上がり、最大 1.5 ブロック/tick
- **レーダーの影絵**（`core/pathlock.js` の `drawRadar`）：Bedrock のパーティクル・エンティティの素材はどれも奥行きの判定があり、壁の向こうに描いたものは隠れる。そこで、目から mob の中心への線が壁に当たるときだけ、その線の上の「壁より 0.2 手前（最大 2.4 ブロック）」に影絵のパーティクルを置き、大きさを「置いた距離 ÷ mob までの距離」倍にする。透視投影では同じ線の上の点は画面の同じ位置に映り、大きさも距離に反比例するので、画面上は mob に重なる。`player.spawnParticle` なので撃ち手にしか見えない。毎 tick 置き直す（寿命 0.1 秒）。ずれが出るのは、カメラが目の位置にない三人称と、tick の間に大きく動いたとき（手前の点は視差が大きい）。ビルボードの `size` は半分の幅・高さとして渡している

## 2.17. HUD 2.0 の毎 tick の値はサブタイトル（2.4.1）

- **なぜ重くなったか**：JSON UI の表示条件はどれも「タイトルの文字列が札を含むか」で、タイトルが変わるたびに、タイトルをバインドしている約 1,080 個の条件が長い文字列（約 350 文字）で評価し直される。2.1.0 で照準の広がりと方位を毎 tick 入れたので、動いている間はタイトルが毎 tick 変わっていた
- **分け方**：毎 tick 変わるのは照準（10 枚）と方位バー（180 枚＋グループ 18）だけなので、この 2 つの値（`HUD2.live`）だけをサブタイトル（`#hud_subtitle_text_string`）で送る。サブタイトル = `AC2L` + 同じ形の札 + 目印。タイトルではこの 2 つを固定（`-`）にするので、向きを変えてもタイトルは変わらない。サブタイトルだけが変わったときは `updateSubtitle` で差し替える（タイトルの表示時間はそのまま）。タイトルを送るときは必ずサブタイトルも一緒に送る（サブタイトルが空になる瞬間を作らない）
- **バニラの表示**：サブタイトルにも目印 `§a§r§s§n` を入れ、`hud_title_text` の `subtitle_frame` を目印入りのときだけ隠す（中身はバニラの定義をそのまま写した）。従来の HUD の知らせは目印がないので、これまでどおりサブタイトルに出る
- **検証**：`Hud2Expr` はタイトル用とサブタイトル用を分け、`live` の値をタイトルで見る式を作ろうとすると生成の時点で止まる。検証 24 は、式が見ている変数とバインドが一致していることと、試験ベクトルの値（タイトルとサブタイトル）で全部の表示条件を評価した結果を確かめる


## 2.18. アドオン全体の実機試験（2.4.2）

- **なぜ**：モックのテストはエンジンの型の検査（「この引数を受け付けるか」）や、イベントが本当に発火するかまでは再現できない。BDS で本物のエンジンを動かし、シミュレートプレイヤー（`@minecraft/server-gametest`、試験用コピーだけ）で全部の武器・投擲物・装備・敵・ボス・構造物・キルストリーク・モードを順にさわる（`tools/bds/fulltest.js`）
- **デバッガ**：Mojang が公開している VS Code 拡張「Minecraft Bedrock Debugger」のプロトコル（長さ 8 桁の 16 進＋1 行の JSON、`protocol` → `stopOnException` → `StoppedEvent` で `stackTrace` / `scopes` / `variables`）を Node で話す小さなクライアント（`tools/bds/debugclient.mjs`）を書いた。例外のたびに止めて記録するので、`safe()` で捕まえて黙っている例外も見える。BDS は待ち受け（`listen`）ではすぐ切るので、クライアント側が待ち受けて BDS から `script debugger connect` でつなぐ
- **見つかったもの**：例外で毎回止まっていた箇所（読み込まれていないチャンクへのレイ、爆発の出どころの型）と、例外は出ないが動いていなかったもの（砲台の向き、地雷の設置）。前者は「例外を投げて捕まえる」のをやめて事前に範囲を縮める。後者は退行テストを足した
- **地雷**：`playerInteractWithBlock` は、使っても何も起きないアイテムでブロックをさわったときに発火しないことがある。ほかの設置物と同じくアイテムのカスタムコンポーネント（`arsenal:gear` の `onUseOn`）で置く
- **爆発の出どころ**：`createExplosion` の `source` はエンジンが型を検査し、受け付けないエンティティ（シミュレートプレイヤーなど）だと例外になり、爆発そのものが起きなかった。受け付けないときは出どころなしで爆発させる（撃った者は `lastAttacker` と爆風ダメージの側で記録している）
- **試合の上書き**：開始フォームの前で「試合がないこと」を確かめていたが、フォームは非同期なので、開いている間に別の人が始められた。`startLobby` 自体で、結果表示・持ち物を戻す前（`phase: "end"`）を含めて試合が残っていれば断る
- **シムでできないこと**：乗車中のジャンプは `inputInfo` に出ないので、銃座は「タップで撃ち続ける」設定のトグルを直接立てて撃つ。フォームはシミュレートプレイヤーには表示されず閉じられもしない（「メニューを開いている」が残る）ので、開くまでの処理だけを通し、その後で状態を戻す

## 2.19. 特殊武器 24 種（2.5.0）

- **方針**：特殊武器は「撃ち方そのものが違う」ことを価値にする。数値違いの複製は作らず、新しい撃ち方 17 種と、既存の撃ち方（照射・プラズマ・ニードル・音波・パルス・電撃）に属性や形を足した 7 種にした。ビルドの検証 21（役割の重複）でカテゴリ内の重なりを確かめる
- **置き場所**：弾を飛ばさない撃ち方は `core/fire3.js`、実体弾は `systems/projectiles.js` の `fireSpecial`（`type: "spec"`。毎 tick の移動はほかの弾と同じくレイで判定し、ブロックをすり抜けない）、地面や相手に残る効果（重力井戸・時間減速・衛星砲・網・麻酔・縫い付け）は `systems/fields.js`。敵 AI のスタンは `fields.js` に登録する形にして、`ai/brain.js` との循環 import を避けた（EMP と同じ）
- **ズルはしない**：スマートピストルは、撃つ瞬間に目から見えている相手にしか曲がらない（壁越しの相手はロックもしない）。反射レーザーは実際のブロックの面で反射し、刃も壁の面で跳ね返る。ブリンクは視線のレイが止まった壁の手前までで、足元と頭の高さが空いている場所にだけ移る。衛星砲は着弾点の真上 40 ブロックに屋根があれば呼べない
- **動けなくする**：Bedrock の鈍足はレベルごとに 15% 遅くなるので、レベル 7（amplifier 6）で移動 0。敵 AI はスタン（射撃と移動の判断を止める）を併用。実機では弱い効果で強い効果が上書きされないので、AI のスタン（鈍足 5）を先にかけてから鈍足 7 を重ねる
- **失敗したときの弾**：ブリンクの着地点がない・衛星砲の空が見えないときは、撃てなかったことを知らせて弾を戻す（撃ったのに何も起きない、を作らない）
- **容量**：1 挺ごとに迷彩 12・光学 2 を含めてアイテムとアタッチャブルが 15 ずつ増えるため、上限を items 2,400・attachables 2,200 に引き上げた（ファイル数 7,929・9.5 MB）
